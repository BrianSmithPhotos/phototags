**Methodology note**: ranks 1-4 and 6-8 were re-judged in a second batch
alongside `gpt-5.5` (judge calls aren't perfectly deterministic run-to-run, so
their scores shifted slightly from the original full-batch run — e.g.
`gemini-3.5-flash` 4.49→4.46, `claude-opus-4.6` 3.93→3.80). Ranks 5, 9-15 (and
`gpt-5.1`, `gpt-4o-mini`, `claude-sonnet-4.5`, `mistral-medium-3-5`,
`gemma4:12b`, `moondream:latest`) retain their scores from the original
full-batch judge run. Differences of a few tenths between runs are judge noise,
not signal — don't read too much into small rank swaps near each other.

## Key takeaways

- **Caveat on #1**: `gemini-3.5-flash` drafted the original ground truth (see
  `generate_ground_truth.py`) before it was hand-edited, so its top spot likely
  still carries some residual advantage. Directionally interesting, not decisive.
- **`gpt-5.5` is not an upgrade over `gpt-5.1` for this task**: despite being
  OpenAI's newer flagship, it scored lower on both accuracy and completeness,
  cost ~12x more ($1.05 vs $0.09 for 41 images), and took ~4x longer (487s vs
  117s). `gpt-5.1` remains the better OpenAI candidate here.
- **Production default holds up**: `gemini-2.5-flash` (current OpenRouter
  default) is mid-pack but by far the best cost/speed tradeoff — far cheaper
  than every model that beats it on score, for only modestly lower accuracy.
- **Local vs. cloud, same weights**: `qwen2.5vl:72b` run locally (48 min, $0,
  3.51/3.02) scores about the same as the identical weights hosted on OpenRouter
  (2.75 min, $0.09, 3.41/2.88) — running it locally buys no quality for a 17x
  time cost.
- **Local models trail the strongest cloud models** on both axes (quality and
  speed) for this task.
- **`moondream:latest` is unusable** for this task — a smoke test confirmed it
  just echoes the prompt's placeholder JSON (`"k1"`, `"k2"`) rather than
  describing the image, consistent with its 19.5% error rate and 1.33 accuracy.

## Dropped from this round

- **`mistral-medium-3.5:latest` (local, 127.7B/~170GB)**: ran for 14+ hours
  without completing a single pass — impractical for this kind of sweep.
  Replaced with the OpenRouter-hosted `mistralai/mistral-medium-3-5` (#13 above).
- **`llama3.2-vision:11b` (local)**: blocked by an open Ollama regression
  (`unknown model architecture: 'mllama'`), not a transient issue — see
  [ollama/ollama#16490](https://github.com/ollama/ollama/issues/16490). Revisit
  once upstream ships a fix.
- **DeepSeek**: no vision-capable model currently available on OpenRouter, so it
  couldn't be included as a candidate.

## Re-running

Per-model generation results live in `eval/results/<model>.json` (gitignored,
regenerate with `uv run python eval/run_candidates.py`). Judge scores live in
`eval/results/judged/<model>.json` (committed) and are produced by
`uv run python eval/run_judge.py`, which batches all candidates for one image
into a single judge call to minimize image-token cost. Set `JUDGE_ONLY` in
`run_judge.py` to a list of model ids to re-judge a subset instead of everyone
(e.g. when adding one new candidate). `uv run python eval/summarize.py` reads
both directories and prints the table above.
